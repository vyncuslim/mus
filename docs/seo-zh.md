# 搜索引擎与分享检查

## 上线前

1. 确认 Vercel 的 **Production** 域名为网站真正使用的域名，并设置 `NEXT_PUBLIC_SITE_URL` 为完整的正式来源地址，例如 `https://dict.vynalthai.com`，不包含路径、查询参数或凭据；修改环境变量后重新部署。不要把其他站点的域名写入自己的配置。自动提供的 Vercel 系统 URL 是备用值；若两者都不可用，规范链接会退回本地地址，不能用于正式收录。
2. 检查正式域名 `/robots.txt` 的 `Sitemap` 地址、`/sitemap.xml`、首页、`/entries`、`/sources` 和几个词条的 `rel="canonical"`。规范 URL 应使用同一正式域名，网站地图中的词条应返回 200 且不跳转。
3. 普通查询 `/?q=...` 返回 `noindex, follow`，但仍允许抓取，这样爬虫才能看到 noindex。词条不存在时返回 404 和 noindex；这不代表该词不存在。当前 Next.js 的动态 404 初始 HTML 可能没有提示正文，词条未找到提示及规则分析需启用 JavaScript。Vercel Preview 环境额外发送 `X-Robots-Tag: noindex, nofollow`，避免预览副本参与收录。
4. 首页、索引和词条包含服务端 HTML；首页查词结果仍由浏览器加载。切换界面语言保存在浏览器中，并不是不同 URL 的独立语言页面，因此不生成虚假的 hreflang。不要仅靠 `?ui=` 标记不存在的语言版本。

## 网站地图的范围

`/entries` 和 `/sitemap.xml` 列出**当前结构化词库中最多 500 条**有可用释义和独立详情页的词条，而不是声称列出全部可搜索词汇。没有数据库或数据库为空、不可达时，按现有服务行为回退到内置 starter 词库；有数据的 PostgreSQL 是权威数据源，不会混入其缺失的 starter 词条。地图按请求生成，不依赖构建时的数据库快照。数据库状态或内容变化时，展示的词条也可能变化。

2023 年大规模释义快照和翻译对照索引用于搜索，并不自动拥有各自的结构化详情页，不应把其数量直接当作网站地图中可收录页面的数量。如果以后需要索引超过 500 条结构化详情，应先设计分页和分片网站地图，并对每个列出的 URL 验证响应、规范链接及内容。

## 部署后由站点所有者完成

- 在 Google Search Console 和其他需要的搜索平台验证正式域名，并提交 `https://你的正式域名/sitemap.xml`。使用 URL 检查工具确认抓取和规范网址；提交不保证收录、排名或收录时间。
- 自定义域可能经过 Cloudflare，其托管内容可能修改实际 `/robots.txt`。检查时 `dict.vynalthai.com` 的一般搜索规则允许抓取，但 Cloudflare 规则另外禁止了 `Baiduspider`、`GoogleOther` 等特定爬虫。`GoogleOther` 不是 `Googlebot`。如需百度收录，请由站点所有者检查相关 Cloudflare 爬虫规则，仅在符合自身政策时调整；不要因此无条件开放 AI 训练爬虫。
- 用目标分享平台的调试工具检查首页、来源页和词条页的标题、描述和分享图片。Cloudflare 图片防盗链或其他安全规则可能拦截来自站外的图片请求；需要站点所有者检查实际响应。应用中的标签无法绕过 Cloudflare 拦截，平台也可能缓存旧预览。
- 检查实际部署的移动端、速度、服务器日志和数据库可用性，必要时在 Search Console 中复查抓取错误。SEO 是持续维护，代码修改不能保证搜索结果位置。
