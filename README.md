# Vynalth Dictionary

A focused, multilingual dictionary built with Next.js, React, TypeScript and Tailwind. Search from the home page; results can include live Wiktionary definitions, a bundled definition snapshot, a curated local entry, or translation equivalents. The interface is available in Simplified Chinese, English and Malay. Learning, favorites and AI tools are not part of the dictionary interface; their old URLs redirect without deleting previously saved browser data.

## Coverage and sources

Coverage varies substantially by language. These are actual counts for the checked-in artifacts, **not** claims to include every word or every word form:

| Source | Included data | What it provides |
| --- | --- | --- |
| [English Wiktionary](https://en.wiktionary.org/) | Live API, availability depends on network and source | Current definitions, examples and search suggestions where available |
| [Vuizur/Wiktionary-Dictionaries](https://github.com/Vuizur/Wiktionary-Dictionaries/tree/be0cfb8d614470bc8b9d9006ddff8b921cd5c2e3), based on Wiktionary/Kaikki | **2,533,552** source entries with senses across **342 language categories**, from a **2023-05-19** snapshot | Backup definitions, generally in English; some source language categories include historical or constructed varieties |
| [Methodox Multilingualism](https://github.com/MethodoxTech/Multilingualism/tree/fe427837f392a90f8d68a3e69c7c9f3c1f716bb9) | **519,230** non-machine translation pairs in **108 languages**, derived from **9,852 English headwords** | Translation equivalents, **not full definitions**. **544,786** machine-flagged source rows were excluded |
| Curated starter set | **49** entries across **12** languages | Detailed entries, including selected Malay morphology, IPA and examples |

The definition index stores 2,895,450 lookup-key records, not 2,895,450 unique words or independent entries. To bound size, most inflected or alternative forms are omitted; where an indexed form matches a different headword, the result identifies the headword. A small, separately attributed 2026 Wiktionary seed covers `mengikut`. Existing spellings and roots are never generated by blindly stripping Malay affixes. Unicode normalization supports case, diacritics and Arabic vowel marks; the starter dataset also supports selected Pinyin/romanized readings. A missing result does not prove a word does not exist.

See [`data/wiktionary-definitions/README.md`](data/wiktionary-definitions/README.md) and [`data/world-lexicon/README.md`](data/world-lexicon/README.md) for exact dataset policy, pinned revisions and reproducible builds. The snapshot is approximately 88 MB compressed; plan deployment storage and memory accordingly.

**Attribution and licences:** lexical content is by Wiktionary contributors. The Vuizur/Kaikki snapshot is provided under **CC BY-SA 3.0 / GFDL**; the Methodox translations are **CC BY-SA 4.0**. Results link to Wiktionary pages whose revision histories identify contributors. Retain attribution and applicable share-alike terms when reusing data. The source page in the app links to the upstream projects and licences.

## Development

Requires Node.js 22.13 or newer within the 22.x line. The package's `engines` setting selects Node.js 22.x for Vercel builds and functions.

```bash
npm ci
npm run dev -- --hostname 0.0.0.0 --port 3000
npm run lint
npm run typecheck
npm test
npm run import:wiktextract -- --dry-run
npm run build
npm run start -- --hostname 0.0.0.0 --port 3000
# In another shell, after starting the server:
npm run test:e2e
```

The app works without a database: the bundled dictionary indexes and curated starter entries are served locally. The browser requests live definitions and autocomplete directly from Wikimedia; these requests reveal the query to Wikimedia and may fail due to network or browser policy. Playback, where available, uses browser speech synthesis and is explicitly labeled as such, not as a native-speaker recording.

## Deploy to Vercel from GitHub

See the [Chinese deployment guide](docs/vercel-zh.md) for step-by-step setup and troubleshooting.

1. In Vercel, choose **Add New → Project**, connect GitHub, and import this repository. Grant Vercel access to the repository in GitHub if prompted. Use the repository root (`.`), the Next.js framework, and the defaults from `vercel.json`; do not set a static `out` output directory.
2. Deploy a branch **that contains this application**. If the changes are still in an open PR, the default `main` branch may not contain them yet: merge the PR after review or create a deployment from the PR branch in Vercel. Vercel's first deployment of a new project is production, even if it comes from another branch; later non-production branches normally create previews. The production branch is configurable under **Settings → Environments → Production → Branch Tracking**.
3. No database or API key is required for the bundled dictionary. Vercel's automatically exposed `VERCEL_PROJECT_PRODUCTION_URL`, then `VERCEL_URL`, supplies the metadata origin; local development falls back to `http://localhost:3000`. If system environment variables are disabled, or to select a custom canonical domain, set `NEXT_PUBLIC_SITE_URL` to your real `https://` origin (no path) for the desired environments and redeploy. A malformed value fails the build. Keep `DATABASE_URL` optional and private; see **Optional PostgreSQL** below.
4. After deployment, check `/`, `/api/health`, `/api/definitions?q=mengikut`, and `/api/world?q=water`. Check Vercel's **Deployments → Resources / Logs** for function sizes, errors, and plan limits. Deployment protection may require authentication before preview URLs can be tested.

`npm run vercel-build` runs the production build and checks that all 256 key shards, every language shard, and the translation index are traced. It also applies a conservative 200 MiB budget to each large route and the union of API traces. This is a preflight, not a guarantee of final Vercel package size or hosted behavior: Vercel may group functions and add runtime files. The checked-in definition snapshot is about 88 MB compressed, so monitor function size, cold starts, memory and bandwidth in your own deployment. Serverless instances do not share the app's in-memory rate-limit counters; use a shared limiter if global abuse protection is required.

### Translating English definitions

Every lookup starts in **human-reviewed mode**. It displays a translated definition only when there is an exact, source-specific record with a translation source, licence, attribution, named reviewer, review date and evidence. **The checked-in review catalogue currently contains 0 records.** Existing localized starter definitions and Wiktionary word equivalents do not have item-level review records here and are therefore collapsed as explicitly unreviewed source data; they are not relabeled as reviewed. When no reviewed translation is available, the English definition remains visible. The original dictionary data and human-reviewed translations can both contain errors; neither mode promises perfection.

To use wider coverage, choose a **definition language**, select **Automatic (unreviewed)** and click **Translate definitions**. The menu offers 91 target-language choices in addition to the English original; availability and quality for each pair depend on the provider and are not guaranteed. The original English and any reviewed translations remain visible. Other English definitions can be translated in batches of at most eight visible senses (approximately 2,000 input characters per batch); use **Translate more** for additional senses. Long definitions are split at paragraph and UTF-8-safe boundaries with a maximum of eight chunks; oversized definitions are left in English rather than truncated. Switching back to reviewed mode hides automatic output and cancels a pending request. A new lookup defaults to reviewed mode again; the target language preference is saved locally.

Automatic translation is **opt-in**: clicking Translate sends the English definitions directly from the browser to [MyMemory](https://mymemory.translated.net/doc/spec.php). The service may use machine translation or translation-memory matches; all output is labeled **automatic and unreviewed**, is not a verified dictionary definition, and can be inaccurate. Fuzzy matches to a different source sentence are not accepted. The third party sees the submitted text, target language and client IP; its [privacy terms](https://mymemory.translated.net/terms-and-conditions) say it may retain submitted segments long-term and share them with service partners. Its documented anonymous quota is [5,000 characters per day](https://mymemory.translated.net/doc/usagelimits.php) and may change or be shared with others on the same network; connectivity, CORS, quota and individual language support can fail. Only successful automatic translations are cached in memory for the current page session; new translations require internet and are not available offline. Tests mock provider responses rather than depending on an external network.

### Adding a genuinely human-reviewed translation

The static catalogue is [`data/reviewed-definition-translations.json`](data/reviewed-definition-translations.json); it is empty until actual reviews are available. Do not promote existing localized or machine-translated text merely because it is present, and do not invent reviewers or review evidence. A real reviewer must check the exact sense and target translation, source licensing and attribution, and create a durable review record. Add the record through a code-reviewed change, run `npm test`, and redeploy. The app has no public self-certification or administration endpoint.

Each catalogue entry must follow `ReviewedTranslationSchema` in [`src/lib/reviewed-definitions.ts`](src/lib/reviewed-definitions.ts):

- `subject`: `origin` (`curated`, `wiktionary-live`, or `wiktionary-snapshot`), exact `sourceUrl`, `sourceVersion`, `headword`, word `language`, `partOfSpeech`, English `definition`, and `senseId`. For curated records, `senseId` is `entry.id/sense.id`; for snapshot/live records it is an empty string. The live version is `live-exact-text`; snapshot versions are reported by the definition API, e.g. `wiktionary-snapshot-2023-05-19`. Every field must match the displayed sense; an unknown or changed version fails closed.
- `target` is a supported target tag other than `en`; `translation` contains the reviewed text.
- `source` contains the translation source `name`, HTTPS `url`, `license`, HTTPS `licenseUrl` and `attribution`.
- `review` contains an identifiable human `reviewer`, a real non-future UTC `reviewedAt` date (`YYYY-MM-DD`), and an HTTPS `evidenceUrl` linking to the review record. Displayed results link to the English source, translation source, licence and review evidence.

Validation rejects missing fields, unsafe links, impossible or future review dates, unsupported target languages and duplicate source-sense/target records. The Next.js build freezes the UTC review-date cutoff for both server and browser, rather than trusting a reader's device clock; tests also check the catalogue against the current UTC date. Validation checks metadata structure only: **software cannot authenticate reviewer identity, confirm that linked evidence supports the review, validate a licence, or guarantee translation accuracy**. A responsible human must verify all of those before publication. Tests contain synthetic review fixtures that are never shipped as actual reviews.

The PWA caches the app shell and up to 100 visited same-origin runtime resources. Only previously cached pages and searches may work offline; **the full dictionary is not downloaded to the browser**. Search and detail APIs validate request parameters, and source markup is converted to inert text.

## Optional PostgreSQL

`DATABASE_URL` may point to a PostgreSQL database for the structured starter/imported entries. Back up existing databases before changing the schema. The large bundled definition and translation indexes are independent of PostgreSQL.

```bash
# Configure DATABASE_URL in .env.local, then apply schema/index changes.
npm run db:push
# Existing databases: fill normalized reading, form and translation lookup indexes.
# Run while imports/writes are stopped. Safe to rerun.
npm run db:backfill-index
# Optional local Wiktextract import, after the schema is ready:
npm run import:wiktextract -- --input /path/to/kaikki.jsonl --lang ms,en,zh-Hans --version YOUR_SOURCE_VERSION
```

Lookup issues indexed, bounded SQL candidate queries across the **whole** table; it no longer preloads only the first 2,000 rows. Exact and prefix candidate sets have limits, so response totals describe the retrieved candidates rather than a guaranteed global count. Reading, form and translation matches for preexisting records require the backfill. An older unmigrated schema can still perform headword lookup, but should be migrated for full support. If PostgreSQL is absent, empty or unreachable, the curated entry service falls back to the starter set.

The importer is limited to the 12 structured-entry language codes and supported Wiktextract parts of speech. The separate bundled snapshot and translation index cover more language categories; their counts must not be conflated with structured entries. Import only appropriately licensed data and preserve provenance.

## API overview

- `GET /api/definitions?q=<word>&limit=<1..80>` — bundled definition snapshot and separately attributed seed.
- `GET /api/world?q=<word>&lang=<code|all>&limit=<1..200>` — translation pairs and prefix suggestions.
- `GET /api/search?q=<word>&source=<structured-code|all>&target=<structured-code|all>&limit=<1..100>` — curated or PostgreSQL entries, with optional POS/Malay filters.
- `GET /api/words/[language]/[word]`, `/api/suggestions`, `/api/languages`, `/api/health` — structured entry details and status. The legacy structured language registry lists 12 codes; global snapshot and translation coverage is reported separately. For `/api/languages`, use `headwordCount`, `hasEntries` and `summary.totalEntries`; for `/api/health`, use `lexicon.totalEntries`. The old `verifiedHeadwordCount`, `hasVerifiedEntries` and `totalVerifiedEntries` fields now return `null`: entry-level verification has not been measured, and the old counts did not establish it. Both endpoints separately report the number of documented definition-translation records.

A host must deploy the checked-in `data/` artifacts and support Node filesystem access; `next.config.ts` includes the compressed shards in output tracing. Set `NEXT_PUBLIC_SITE_URL` if your platform does not supply a Vercel deployment URL. On serverless platforms, check function size and memory limits before deployment.
